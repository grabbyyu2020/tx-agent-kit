# tx-agent-kit

Agent-first starter for Effect HTTP + Temporal + Next.js + Drizzle. `CLAUDE.md` imports this file, so Claude Code and Amp read the same instructions (OPS-01).

Humans steer intent and acceptance criteria. Agents implement, validate, and iterate against mechanical checks. When an agent fails repeatedly, improve the scaffolding (constraints, lints, tests, scripts) rather than adding prose.

## Before you change code

**Load the `project-constraints` skill before writing or changing any code, config, migration, or test.** It holds every rule for this repository with the lint or script that enforces it, including the process rules (`OPS-*`) for dev servers, worktrees, gates, and CI. Read the references for the paths you will touch, write `Constraints: <IDs>` into your todo list, and put the same line plus the reference paths into every subagent brief. Subagents load this file too, so the same rule binds them.

## AI workflow (pstack)

This repository uses [pstack](.skill-sources/README.md) as its only agent workflow. Its skills live in `.claude/skills/` and its subagents in `.claude/agents/`, generated by `pnpm pstack:sync` (OPS-02).

- Invoke the `poteto-mode` skill and follow it when a task touches more than one file, changes a signature other files call, involves a design or architecture choice, or is a bug or performance issue whose cause is unknown. For a contained one-file change with an obvious test, a question, or a one-line edit, work directly and verify on the real artifact.
- When the intent is already specific, enter that skill directly: `tdd`, `architect`, `how`, `why`, `arena`, `interrogate`.
- `.agents/playbooks/constraints.md` extends pstack's Feature, Bug fix, Refactoring, Perf issue, Hillclimb, and Opening a PR playbooks with this repository's constraint loading, worktree helper, and quality gates. Apply it whenever poteto-mode picks one of those playbooks.
- pstack spawns delegates with `subagent_type: "poteto-agent"`. In Amp, which has no `Agent` tool or subagent types, run the delegate's brief with Amp's own subagent tool and point it at `.claude/skills/poteto-mode/SKILL.md`; skip steps that need a missing capability and say so.

## Stack

- `apps/web`: client-only Next.js SPA (no SSR, no `app/api`)
- `apps/api`: Effect HttpApi server
- `apps/worker`: Temporal worker + workflows
- `apps/mobile`: Expo React Native
- `apps/docs`: Fumadocs documentation site
- `packages/core`: DDD domain logic (Effect services)
- `packages/contracts`: shared schemas, event types, permissions
- `packages/temporal-client`: Temporal workflow types + event schemas
- `packages/infra/*`: DB, auth, logging, observability, AI
- `packages/testkit`: test utilities + integration harness
- `packages/tooling/*`: ESLint configs, scaffold CLI, tsconfig, vitest configs

## Local development

Rules: OPS-03, OPS-04.

```bash
pnpm dev          # infra + Temporal + API (4000) + web (3000) + worker
pnpm dev:api      # individual services, once infra is up
pnpm dev:web
pnpm dev:worker
pnpm infra:ensure # shared Docker infra: Postgres, Redis, OTEL, Jaeger, Spotlight, ...
```

- Dev-only login shortcut: with the web app running, open http://localhost:3000, click "Open developer utilities", and choose "Fresh free org" or "Fresh Pro + $20 local credit" (use the Pro preset for billing-gated features).
- Sentry Spotlight starts with `pnpm infra:ensure` and receives errors and traces from web, api, and worker. The `spotlight-local` MCP server exposes them. See `apps/docs/content/docs/observability/spotlight.mdx`.

## Worktrees

Rules: OPS-05, OPS-06; shared infra and ports: TEST-10, TEST-14.

```bash
./scripts/worktree/create.sh feat/my-feature main
cd .worktrees/my-feature
```

The helper sets up `.env`, ports, the Temporal task queue, and a database schema, so gates can run in parallel across worktrees.

## Quality gates

Rules: OPS-07, OPS-08, OPS-09.

- `pnpm lint:quiet`, `pnpm type-check:quiet`, `pnpm test:quiet`.
- `pnpm test:integration:quiet` runs only projects affected since `origin/main` (`--plan` shows the decision, `TX_INTEGRATION_FULL=1` forces the full suite). CI always runs the full suite.
- `pnpm test:integration:full` and `:ci-only` include slow suites.
- `pnpm test:db:pgtap` for database trigger contracts.
- `pnpm ci:check --watch` follows CI for the pushed commit.

`pnpm lint` runs ESLint (`packages/tooling/eslint-config/`), the structural checks in `scripts/lint/` (including `enforce-agent-workflow.mjs`, which keeps this workflow consistent), shell invariants, and jscpd.
